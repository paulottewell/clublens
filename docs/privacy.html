Section 1

What ClubLens is

ClubLens is a single HTML file that runs entirely within a web browser on the user's own device. It has no backend, no server, and no network connectivity of any kind. It is distributed as a standalone file that can be saved locally and opened without an internet connection.

ClubLens is a tool, not a service. The school downloads the file and operates it entirely within its own environment. The developer of ClubLens has no access to any data processed using the tool at any time.

Section 2

Controller and processor status

Because ClubLens processes data entirely within the school's own device and environment — with no data transmitted to any external party — there is no processor relationship to establish.

The school (or trust) is the sole data controller. The developer of ClubLens does not receive, process, store, or have any access to pupil data at any point. An Article 28 Data Processing Agreement is therefore not required.

Schools and trusts should satisfy themselves that their existing lawful basis for processing pupil data via their MIS covers the use of local analytical tools of this nature. Guidance on this is set out in Section 4 below.

Section 3

ClubLens reads a single export file produced by Bromcom (the school's MIS). No other data is required or accepted. The following fields are used from that file:

ClubLens reads only the fields listed above from the Bromcom export. All other fields in the export file are ignored.

Section 4

What ClubLens does not do

  • Does not transmit any data — pupil data never leaves the user's browser
  • Does not store pupil data permanently — all data is cleared when the tab is closed or the page is refreshed
  • Does not use cookies of any kind
  • Does not use analytics, tracking, or telemetry services
  • Does not connect to any external API or third-party service
  • Does not require an internet connection to function
  • Does not create user accounts or profiles
The only exception to the above: ClubLens saves any notes entered in the Action Plan tab to the browser's localStorage. This data remains on the local device only, is not transmitted anywhere, and can be cleared by the user at any time by clearing their browser's local storage. Notes stored in this way do not contain pupil data unless the user manually enters it — ClubLens does not write pupil data to localStorage automatically.

Section 5

Lawful basis for processing

Schools and trusts using ClubLens to analyse pupil participation data should identify an appropriate lawful basis under UK GDPR Article 6. The following basis is likely to apply in most school settings:

Article 6(1)(e) — Public task. Schools have a statutory duty under the Education Act 1996 and subsequent legislation to promote the wellbeing and equal access to opportunities of all pupils, including those with protected characteristics and those receiving Pupil Premium funding. Analysing participation in enrichment activities to identify and address inequity falls clearly within this public task.

For the processing of special category data (SEN status, LAC status, Pupil Premium as an economic circumstance indicator), schools should additionally identify a condition under Article 9. The following conditions are likely to apply:

Special category data Suggested Article 9 condition
SEN status (EHCP / SEN Support) 9(2)(b) — processing necessary for obligations in the field of employment, social security, and social protection
Looked After Children status 9(2)(b) or 9(2)(f) — legal claims / vital interests in a social care context
Pupil Premium (Ever FSM 6) This is an administrative flag rather than a protected characteristic; schools should confirm their existing basis for processing this data within their MIS covers analytical use

Schools should document their lawful basis in their Record of Processing Activities (ROPA) where required. DPOs with questions about the appropriate basis for their specific context are welcome to contact the ClubLens developer using the details in Section 7.

Section 6

Data subject rights

Because ClubLens retains no pupil data once the browser session ends — and transmits no data externally at any point — data subject rights requests (access, erasure, rectification) relating to ClubLens should be directed to the school's MIS system (Bromcom) rather than to ClubLens itself.

The school, as data controller, is responsible for managing data subject rights in relation to all pupil data it holds and processes, including processing carried out using local tools such as ClubLens.

Section 8

Do schools need to complete a DPIA?

A Data Protection Impact Assessment (DPIA) is required under UK GDPR where processing is likely to result in a high risk to individuals. Given that ClubLens:

  • Processes data entirely on the school's own device, with no external transmission
  • Does not create new data — it only analyses existing MIS data the school already holds
  • Retains no data beyond the active browser session
  • Involves no automated decision-making or profiling with legal or significant effect

…it is unlikely that a formal DPIA will be required in most cases. However, schools processing data for pupils who are subject to safeguarding plans, or in contexts where the trust's DPO advises additional caution, should apply their standard DPIA threshold assessment in the usual way.

Schools that do wish to complete a DPIA for ClubLens are welcome to request a completed draft DPIA document from the developer. Contact details are in Section 7.
